# Mayday Landing 发布前清单

功能与构建说明见 [README](../README.md)，探针版用法见 [实机测试说明](testing.md)。本清单按顺序执行，每一项都要留下证据（录制文件名、截图或日志行）。

## 0. 两个包的区别

| 包 | 用途 |
|---|---|
| `mayday-landing-auto-0.2.0-probe.maydaymod`（`pack.ps1 -Probe`） | 实机验收用。带探针，自动录制 |
| `mayday-landing-{auto,advisor}-0.2.0.maydaymod`（`pack.ps1`） | 待发布的正式版，名称带 “(Experimental)”。探针和自动录制默认关闭 |

两者都输出到 `dist/landing/`，内嵌 `LandingAssist/Models/candidate.json`（`bptt-z2` 权重，只含推理字段，SHA-256 `0636c98f593c23dc0119aa4710fb9f430148fc9fd0d4a3e53421571783db3fd5`）。安装包里的 zip 时间戳会让每次构建的包哈希不同，所以发布时要记录**实际上传那一份**的 SHA-256。

当前这次构建（2026-11-23）的正式版 SHA-256：

- Auto：`7540674c6f6cf9ee5dc9f1cc4c252a139e63cd7244ac7b400fceb8cf6f453e1f`
- Advisor：`983e91d256c5732be071027e4f4e333c06c1cfab1e18b3a49750f7f9ef3185e2`

## 1. 实机验收（用探针版，以房主身份）

每项至少飞一趟。遇到异常时按 Shift+F6 打标记，飞完保留 `UserData/MaydayLanding/auto/rec/` 整个目录，用于分析。

| # | 场景 | 通过标准 | 结果 |
|---|---|---|---|
| 1 | 进游戏，不坐驾驶座 | 面板出现在飞机卡片下方，用圆体字，提示“未在驾驶座”；没有红色告警 | ☐ |
| 2 | 坐驾驶座，地面无目的地 | 显示“等待进近数据”（中性颜色），没有大块空白 | ☐ |
| 3 | 打开菜单、隐藏 HUD、切换视角 | 面板和飞机卡片一起隐藏或滑走，再一起出现 | ☐ |
| 4 | 晴天，全自动，手飞到窗口附近 | 状态从“全自动 · 预位”变为自动接管；穿五环；接地下沉率 < 2.5 m/s（不触发 HardLanding）；滑跑时反推开、10 m/s 收起；停稳后拉驻车制动，然后交还 | ☐ |
| 5 | 原生 AP 在飞时切到全自动 | 进入窗口后 AP 断开，模组接管；日志有“已预位：断开原生自动驾驶” | ☐ |
| 6 | 窗口外预位 | 面板写出还差的条件（距离、横向偏差等）；进入窗口后自动接管 | ☐ |
| 7 | 接管中动杆 | 立即交还，模式回到“建议”；松杆后**不会**重新接管 | ☐ |
| 8 | 接管中按 F7 | 断开并回到“建议” | ☐ |
| 9 | 不放起落架进近 | 一直提示放起落架；离地 65 m 时自动复飞；复飞后仍不放则交还，不会带着收起的起落架落地 | ☐ |
| 10 | 滑跑后半段游戏导航切换航段 | 一直刹到停稳，不会提前交还；录制里有 `runwayLatched` | ☐ |
| 11 | 大风天气（gusts 或 low_vis_windy），全自动 | 能落地；记下有无翼尖擦地（Collision）和 HardLanding；坠机数必须为 0 | ☐ |
| 12 | Advisor 版单独安装 | F7 只隐藏面板；不会产生任何操纵 | ☐ |
| 13 | 同时装了旧的 AutoFlight | 检测到另一个控制器时进入只读并提示；按键不冲突（F8、F9 归 AutoFlight） | ☐ |
| 14 | （可选）客户端驾驶，双人联机 | 能显示建议；接管只在延迟 < 0.3 s 时允许；否则交还并给出提示 | ☐ |

**否决条件**（出现任何一条，就不能发布 Auto 版）：

- 发生原生坠机（下沉率 > 8 m/s 或坡度 > 30°）；
- 动杆后不能立即交还，或交还后又自行重新接管；
- 交还后反推还开着；
- 带着收起的起落架接地；
- 游戏报错或崩溃（看 MelonLoader 日志）。

## 2. 修复与回归

- [ ] 对录制运行 `probe_report.py` 和 `replay_trace.py`，逐条确认上表的结果。
- [ ] 修复发现的问题；每处修复都要补测试，并跑通 C# 测试（`pack.ps1` 会自动运行）和 Python 测试。
- [ ] 修改过的项目重新实机验证一次。

## 3. 打正式版

```powershell
.\LandingAssist\pack.ps1
```

- [ ] 输出中五项 `PASS` 全部出现，0 个错误。
- [ ] `manifest.json` 里的名称带 “(Experimental)”，版本号正确；如有修复，版本号要递增，例如 `-Version 0.2.1`。
- [ ] 记录两个包的 SHA-256，更新到本文和发布说明里。
- [ ] 确认内嵌的模型：默认是 `LandingAssist/Models/candidate.json`（`bptt-z2`）。
- [ ] **自己的电脑：** 探针版已经把 `Probe = true`、`AutoRecord = true` 写进了 `UserData/MelonPreferences.cfg`。换成正式版后要把这两项改成 `false`，否则仍会录制。新玩家的默认值是关闭的。

## 4. 玩家说明（随包发布）

- [ ] 写明安装方式：通过 Mod Manager 导入，只装一个包（推荐 Auto）。
- [ ] 写明操作：F7 切换建议 / 全自动，F5 复飞，F6 录制；动杆即可接管。
- [ ] 写明它不会做什么：不会放起落架和襟翼，不负责起飞和航路飞行，不负责滑行。
- [ ] 写明已知限制：
  - 实验性功能；
  - 只在房主单人模式下验证过；
  - 大风天气偶尔会出现翼尖擦地损伤；
  - 巡航构型（速度快、起落架收起）下预位的表现还不确定；
  - 游戏更新后可能失效（面板会退回简易样式，其余功能可能停用）。
- [ ] 写明出问题时请提供：MelonLoader 日志，以及打开 F6 录制得到的文件。

## 5. 发布节奏

1. **小范围测试：** 发给两三位群友，先发 Advisor 版和 Auto 版都可以，Auto 版注明是实验功能。收集日志和录制，问题修完后再进入下一步。
2. **公开发布：** 小范围测试至少 5 趟全自动落地都没有触发否决条件之后再公开。
3. **回滚：** 保留上一版的包和 SHA-256；有问题就让玩家在 Mod Manager 里换回上一版。替换已安装的 DLL 前先备份旧版本。

## 6. 发布后跟进（不阻塞发布）

- 用玩家的大风天气录制核对孪生的擦地预测（约 7% 的擦地损伤）。
- 双人联机下客户端驾驶的验证。
- 游戏更新后重新检查：导航字段、`CmdPilotAction` 编号（2 = 驻车制动，3 = 断开 AP，4 = 反推）、`UIF` / `UITheme` / `PlaneStatusWidget`。
